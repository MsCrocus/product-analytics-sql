# Product Analytics with SQL: Funnel, Retention and A/B Test

SQL analysis of a **synthetic** mobile-app dataset. The project answers the questions a product team asks
after a release: *Can we trust the data? Where do users drop off? Which channels convert? Do users come back?
Did the new onboarding flow actually win?*

> **Data note:** the dataset is fictional and generated by `scripts/generate_data.py` (seeded, reproducible).
> It does not come from any real company or app. The onboarding experiment effect was built into the generator,
> so the findings demonstrate the *method*, not real-world results.

## What this project shows

- Data validation before analysis (duplicates, orphan rows, impossible timestamps, inconsistent values)
- Funnel analysis and segment breakdowns with CTEs and conditional aggregation
- Cohort retention (D1 / D7) with date arithmetic and self-joins
- A/B test analysis: sample ratio check, conversion per variant, lift and a two-proportion z-test
- Window functions: `LAG`, `FIRST_VALUE`, `RANK`, rolling averages, running totals

## Data model

| Table | Rows | Description |
|---|---|---|
| `users` | 5,000 | One row per user: signup date, platform, country, acquisition channel |
| `events` | 47,412 | Event log: `app_open`, `onboarding_start`, `onboarding_complete`, `paywall_view`, `trial_start`, `purchase`, `feature_use` |
| `subscriptions` | 326 | One row per paid subscription (monthly or annual plan) |
| `experiment_assignments` | 5,000 | Variant (`control` / `variant`) of the `onboarding_v2` experiment |

Signups run from 2026-01-01 to 2026-03-01, events until 2026-03-31.

**Planted data-quality issues** (so the validation step has something to find): 30 duplicate events,
15 orphan events, 20 events dated before signup, 40 users without country, 25 users with inconsistent
platform casing. `sql/00_schema_and_views.sql` defines `users_clean` and `events_clean` views that fix them,
and every later query uses those views.

## Queries

| File | Business question |

| `00_schema_and_views.sql` | Tables and cleaning views |

## How to run

Requires Python 3.9+ (standard library only). SQL is written for **SQLite 3.25+**.

```bash
python scripts/generate_data.py          # optional: CSV files are already in /data
python scripts/load_db.py                # builds product_analytics.db from the CSVs
python scripts/run_query.py sql/03_onboarding_funnel.sql
python scripts/ab_test_significance.py   # z-test for the experiment
```

Prefer a GUI? Open `product_analytics.db` in [DB Browser for SQLite](https://sqlitebrowser.org/) and paste any query.

## Key findings

**Data quality.** All planted issues were detected (30 duplicates, 15 orphans, 20 pre-signup events,
40 missing countries, 25 non-standard platform values). One subscription lost its matching `purchase` event
after cleaning, which shows why reconciliation checks between tables matter.

**Funnel (5,000 signups).**

| Step | Users | % of previous | % of signups |
|---|---|---|---|
| Signup | 5,000 | | 100.0 |
| Onboarding started | 4,604 | 92.1 | 92.1 |
| Onboarding completed | 2,729 | 59.3 | 54.6 |
| Paywall viewed | 2,231 | 81.8 | 44.6 |
| Trial started | 693 | 31.1 | 13.9 |
| Purchase | 325 | 46.9 | 6.5 |

The two biggest drops are onboarding completion (59.3% of starters) and paywall to trial (31.1%).

**Channels.** Referral converts best (8.3% of users purchase; 60.0% of its trials convert) and paid social
worst (5.4%; 39.2%). Organic brings the most revenue (43.9% share) because of its volume, while referral has
the highest revenue per user (about $1.11 vs $0.56 for paid social).

**Retention.** For full signup weeks, D1 retention ranges from 25.9% to 30.0% and D7 from 12.5% to 16.8%.
With roughly 570 users per cohort, differences of a few points between weeks should be read with caution.

**A/B test `onboarding_v2`.** Users were split 49.7% / 50.3% (no sample ratio problem).

| Metric | Control | Variant | Absolute lift | p-value |
|---|---|---|---|---|
| Onboarding completion (primary) | 51.19% | 57.93% | +6.74 pp | < 0.001 |
| Trial start (secondary) | 11.40% | 16.29% | +4.89 pp | < 0.001 |

Recommendation based on these numbers: roll out the new onboarding flow, and keep monitoring paid conversion,
because the purchase sample is still small (135 vs 190 purchases).

## Limitations and next steps

- Synthetic data: lifts are larger and cleaner than most real experiments.
- The significance test covers each metric separately, with no multiple-testing correction or segment analysis.
- The sample ratio check is descriptive (no chi-square test).
- Possible extensions: time-to-convert analysis, retention curves beyond D7, a Looker Studio or Power BI dashboard
  on top of the funnel and retention queries, and running the same logic on BigQuery.
